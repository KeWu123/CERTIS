# Exploratory structural study protocol — 2026-10-16

This is new author-side exploratory evidence, frozen before any execution of its policies. It is not an amendment of an earlier locked protocol or a retroactive preregistration. No existing reviewer reports are inputs. No core algorithm or existing driver is modified.

## Targets and separation of axes

The complete target grid is N in {128,512,2048}, K in {2,8,32}, primary key-size law uniform or Zipf exponent 1.5, secondary membership fraction rho in {0,.25}, and seed in {101,202,303}: 108 targets. N is the total identities, split equally between disjoint left and right oracle namespaces. Deterministic largest-remainder allocation realizes each key-size law on each side. Identity assignments are independently permuted by side. Every identity has exactly one primary key; floor(rho*N/2) identities per side receive exactly one distinct secondary key. Empty keys remain in the input. Repeated matching keys produce distinct SQL bag derivations.

The generator's primary, secondary, and label RNGs are independent SeedSequence streams. Primary assignment and truth are paired across rho. Label probabilities depend only on primary key index, cycling [.15,.5,.85]. No outcomes, seeds, targets, or failures are tuned, removed, or replaced. Source hashes and all generated inputs are frozen in FREEZE.json before checks and grid execution; frozen_sources/ retains exact copies.

## Policies and accounting

Every target executes exact right-first, exact compressed-cover, dynamic_max_degree, Ddegree (audit + feedback, helper=False), and C (paid cut + audit + feedback). The 54 rho=0 targets also execute Eall_mask (exact snapshot count allocation + audit + feedback), for 594 executed and actual DuckDB-materialized policy cells. Eall_mask rejects repeated identities. Policy execution uses existing verified APIs only.

The audit budget is max(1,N//16) per full side for Ddegree and Eall_mask, and per remaining side after C's paid cut, capped at that side's population. Delta=.05, loss allowance=.1, batch size128, and the existing 65 nested mask cardinalities remain unchanged. Ddegree/Eall_mask audit per key-side domains; C audits its eight fixed side/score-rank bins, conditional on post-cut unknown membership. Each policy owns a cold cache. Every new oracle fact is charged once through Oracle.acquire. Every helper access is charged through Oracle.use_scores; C purchases all N helper identities. All helper scores are artificially fixed at .5 and uninformative. Oracle and helper tapes each charge one synthetic input token and one synthetic output token per identity. These are unit-cost fixtures, not estimated real token usage, prices, inference latency, or live-model results.

Complete requests equal oracle plus helper requests. Complete tokens include both directions for both providers. Report phase costs, CPU process time, elapsed time, policy timings, actual lost/full output counts, actual loss, interval coverage failures, conflicts, exceptions, and all axis aggregations. Every cell opens a fresh SQL connection so setup/reference/materialization are not transferred between methods. Measured CPU includes policy execution, DuckDB setup/reference/returned materialization, and validation; it excludes input generation and artifact serialization. Existing algorithm timing fields have narrower scopes and are not substituted for complete CPU. Outputs are actually materialized in DuckDB and compared with full-tape bags. Independent factorized counts verify every output; tiny cases additionally compare explicit key/identity triples. A descriptive posthoc minimum of the three executed exact controls may be reported but is not an executable comparator policy.

## Checks before full grid

Freeze all sources and input hashes, then run distinct checks for generator side/primary/secondary invariants and rho pairing; fixed-seed audit draws and confidence budgets; exact finite-population interval coverage for every population<=8; oracle and helper cache charging; negative/all-positive/mixed tiny outcomes; explicit SQL bag equality; and Eall_mask eligibility rejection. A failed check stops the full grid. Confidence failures in the study are observations to retain, not assertions to remove. A covered cell violating the loss allowance is separately flagged. Exceptions are recorded with target, policy, traceback, elapsed/CPU, and remain in the cell roster. Resource constraints are documented explicitly rather than silently reducing scope.

## Geometry-only supplement

Use N in {8,12}, K in {2,4}, uniform primary law, rho in {0,.25,.5,1}, and all three fixed seeds: 48 targets. For every target, construct intervals centered on its true counts with slack0 or1, clipping to capacities; these are explicitly covered geometric constraints, not statistical audits. Use cache fractions {0,.25,.5}, a fixed independently seeded cache order, and 11 masks (empty/full/left/right; degree prefixes1/4,1/2,3/4; four seeded random half masks). Rescue cached positives by excluding all cached identities from the effective unknown discard mask.

Enumerate all 2^N Boolean assignments, impose shared identity constraints, all key-side intervals, and cache facts, then maximize 9*full-10*returned. Compare against the sum of copied per-key supports from the existing integer envelope (which drops cross-key identity equalities). Retain every mask, cache, interval mode, world count, and sharpness gap. Check copied support never understates global Boolean support, and rho0 agrees exactly. Report rates and sizes of strict gaps and certification gaps without selecting successes. These records characterize envelope geometry only, not a statistical guarantee or full query cost.

## Reproducibility and completion

Use python -X utf8 -B run_structural.py {freeze,checks,grid,geometry,summarize}. Inputs are fixed and contain labels only for the harness; algorithms receive Case metadata and charged Oracle facts. No policy may inspect truth except via Oracle.acquire. Post-run raw inspection checks all594 bindings, source and input digests, phase/request/token arithmetic, true paid facts, actual SQL materialization statements, exact target-policy roster, and independent counts. All raw results are gzip JSON and retained. Outputs are cells.csv, axis_summary.csv, paired_comparisons.csv, geometry_records.json, geometry_summary.csv, checks.json, raw_inspection.json, and RESULTS.md.
